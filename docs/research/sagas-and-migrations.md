# Generated undo: saga compensations and data down-migrations

Generated by `scripts/saga_migration_study.py`.

## Sagas under concurrent traffic

5,000 random checkout sagas (reserve stock → charge with a fee → award loyalty points capped at 1,000 → book shipping), with other transactions writing the same records in between. When a step fails, completed steps are compensated, and the result is compared with *keep what other transactions committed, remove the saga's effect*.

| loyalty step written as | compensation | correct | fails loudly | silently wrong |
|---|---|---:|---:|---:|
| re-check cap on current balance | Reverie (step run backward) | 3,080 | 82 | 0 |
| re-check cap on current balance | snapshot restore | 1,404 | 0 | 1,758 |
| re-check cap on current balance | hand-written | 2,786 | 0 | 376 |
| decide on recorded input, apply a delta | Reverie (step run backward) | 3,162 | 0 | 0 |
| decide on recorded input, apply a delta | snapshot restore | 1,404 | 0 | 1,758 |
| decide on recorded input, apply a delta | hand-written | 2,786 | 0 | 376 |

3,162 sagas needed compensation. In 208 of them another transaction *read* the saga's effects (a dirty read: a sale limited by reserved stock, points earned against a raised balance). No compensation can undo another transaction's decision, so those are judged against what was committed.

Writing the capped step the obvious way is rejected by the checker: *irreversible update: `points` reads the value being changed*.

## Data migrations

A v1 → v2 migration over 5,000 rows: convert prices in USD/EUR/GBP to USD cents (rounding), collapse a 6-value status to 3, pack three flags, drop a column.

| down-migration | rows restored exactly |
|---|---:|
| **Reverie (migration run backward)** | **5,000 / 5,000** |
| hand-written data down-migration | 0 / 5,000 (1,238 ignoring the dropped column) |
| schema-only (old columns come back empty) | 10,855 of 35,000 cells |

The witness that makes the rollback exact (rounding remainders, original currency, the dropped status bit, the archived column) takes 30.7 KiB coded, against 50.2 KiB for a full backup of the v1 columns (1.6x). Most of it is the archived column itself (19.7 KiB), which no rollback can avoid keeping; the conversions, the status and the flags need only 10.9 KiB. Dropping a column without archiving it is rejected: *irreversible update: `legacy_score[...]` reads the value being changed*.

### Rolling back after new writes

500 rows were edited in the v2 schema after the up-migration, then the down-migration ran.

- Unedited rows restored exactly: **True**.
- Rows flagged by a non-zero leftover in the witness columns: 266 (unedited rows flagged: 0).
- Rows silently inconsistent (not flagged, and migrating up again does not reproduce the edit): **0**.

| original currency | edited | flagged | rollback then up reproduces the edit |
|---|---:|---:|---:|
| EUR | 148 | 148 | 71 |
| GBP | 118 | 118 | 44 |
| USD | 234 | 0 | 234 |

USD rows carry the user's edit back exactly. For converted currencies an edited amount often has no exact source-currency equivalent; every edited converted row is flagged for review rather than silently rounded. The flag is conservative: about half the flagged rows would have round-tripped.
